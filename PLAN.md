# План: учёт питания в столовой по NFC-карточкам

Версия плана: 1 (14.10.2026). Основа: файл `Концепт`.

## 1. Что нужно сделать (из концепта)

| # | Требование | Комментарий |
|---|------------|-------------|
| 1 | SQL-база учеников: дата, ФИО, группа, завтрак, обед, id NFC-карточки | Хранилище: SQLite. Дата — дата прикладывания карточки |
| 2 | Приложили карточку → окно с данными ученика и кнопками «Завтрак» и «Обед» | Кнопка списывает соответствующий приём пищи |
| 3 | Режим без NFC: имитация прикладывания карточки | Нужен с первого этапа, для разработки и тестов |
| 4 | Каждый день автоматически выгружать данные в Excel | Один файл `.xlsx`, каждый день на отдельном листе |
| 5 | Каждый день сбрасывать отметки «завтрак» и «обед» | Для нового дня ученик снова может получить питание |

## 2. Что в концепте неясно и как я предлагаю это решить

1. **Сброс отметок уничтожает историю.** Если каждый день обнулять поля «завтрак» и «обед», за прошлые дни ничего не останется. Тогда выгрузка в Excel — единственная копия, а если выгрузка не прошла (компьютер был выключен), данные за день потеряны.
   **Предложение:** вести отдельный журнал выдачи, где каждое списание — одна строка с датой и временем. «Сегодня уже получил завтрак» вычисляется по журналу за текущую дату. Тогда для пользователя сброс происходит сам в полночь, ничего не нужно удалять, а выгрузку можно повторить за любой день.
2. **Поле «дата».** ✅ *Уточнено:* это дата прикладывания карточки. Она относится не к ученику, а к каждому списанию, поэтому хранится в журнале выдачи (`meals.meal_date` и время `meals.issued_at`), а не в таблице учеников. Записывается в момент нажатия «Завтрак» или «Обед». Если карточку приложили, но кнопку не нажали, ничего не записывается.
3. **Диапазон id карточки «от 0 до int64.max».** UID у распространённых карт (MIFARE Classic, NTAG) занимает 4 или 7 байт. 4-байтовый UID может быть больше `int32.max` (до 4 294 967 295), а 7-байтовый не помещается и в 32 бита.
   **Предложение:** хранить id как `INTEGER` SQLite (64 бита) или как hex-строку UID. Если карточки свои и номер на них записан программно, ограничение int32 подходит. *Нужно уточнить, какие карты и какой считыватель.*
4. **Повторное прикладывание.** Что делать, если завтрак уже списан? Предложение: кнопка «Завтрак» неактивна, рядом надпись «уже получен в 08:12».
5. **Неизвестная карточка.** Предложение: окно «Карточка не зарегистрирована» и (в режиме администратора) переход к регистрации ученика на эту карточку.
6. **Кто заносит учеников.** В концепте этого нет. Нужен хотя бы простой экран для добавления и редактирования учеников или импорт списка из CSV/Excel.

## 3. Архитектура

Стек уже выбран в текущем каркасе: **Vala + GTK 4 + libadwaita**, сборка через **meson**, интерфейс в `.ui`-файлах (Cambalache).

```
┌──────────────┐  card_detected(uid)  ┌───────────────┐
│ CardReader   │ ───────────────────▶ │ Application   │
│  ├ Simulated │                      │  (контроллер) │
│  └ PcscReader│                      └──────┬────────┘
└──────────────┘                             │
                                ┌────────────┼─────────────┐
                                ▼            ▼             ▼
                         ┌───────────┐ ┌──────────┐ ┌─────────────┐
                         │ Database  │ │ UI-окна  │ │ DailyJobs   │
                         │ (SQLite)  │ │ (.ui)    │ │ (экспорт)   │
                         └───────────┘ └──────────┘ └─────────────┘
```

- **`CardReader`** — интерфейс с сигналом `card_detected (uint64 uid)`. Реализации:
  - `SimulatedReader`: поле ввода id и кнопка «Приложить карточку» (этап 1);
  - `PcscReader`: настоящий считыватель через PC/SC (`pcscd` + `libpcsclite`), опрос в отдельном потоке (этап 3);
  - если считыватель работает как клавиатура (печатает UID и Enter), хватит варианта `SimulatedReader` с невидимым полем ввода.
- **`Database`** — обёртка над `sqlite3` (vapi есть в комплекте valac), все SQL-запросы в одном месте.
- **`DailyJobs`** — таймер GLib до ближайшей полуночи и проверка при запуске: если выгрузка за прошлый день не сделана, сделать её.
- **`ExcelExporter`** — запись `.xlsx` через `libxlsxwriter`. Для неё нужно написать небольшой `.vapi`, около 10 функций.

## 4. Схема базы данных

```sql
CREATE TABLE students (
    id          INTEGER PRIMARY KEY,
    card_uid    INTEGER NOT NULL UNIQUE,   -- id NFC-карточки
    full_name   TEXT    NOT NULL,          -- ФИО
    group_name  TEXT    NOT NULL           -- группа
);

CREATE TABLE meals (
    id          INTEGER PRIMARY KEY,
    student_id  INTEGER NOT NULL REFERENCES students(id),
    meal_date   TEXT    NOT NULL,          -- дата прикладывания, 'YYYY-MM-DD'
    meal_type   TEXT    NOT NULL CHECK (meal_type IN ('breakfast', 'lunch')),
    issued_at   TEXT    NOT NULL,          -- время прикладывания, 'HH:MM:SS'
    UNIQUE (student_id, meal_date, meal_type)  -- не больше одного завтрака/обеда в день
);

CREATE TABLE exports (
    export_date TEXT PRIMARY KEY,          -- по какой день включительно выгружено
    file_path   TEXT NOT NULL,
    done_at     TEXT NOT NULL
);
```

Ограничение `UNIQUE` в `meals` защищает от двойного списания даже при двойном нажатии.

Буквальный вариант из концепта (флаги `breakfast`/`lunch` в `students`, которые обнуляются каждый день) **не подходит** для выгрузки «один файл, лист на каждый день». `libxlsxwriter` не умеет дописывать лист в существующий файл, только создаёт файл заново. Значит, программе нужны данные за все прошлые дни, а после сброса флагов их нет. Журнал `meals` решает это: из него файл пересобирается целиком (подробнее в разделе 6).

## 5. Интерфейс

1. **Главное окно (ожидание).** «Приложите карточку», часы, счётчики за сегодня (выдано завтраков/обедов). В тестовом режиме внизу поле «id карточки» и кнопка «Приложить».
2. **Окно ученика** (появляется при прикладывании). ФИО, группа, статус за сегодня, большие кнопки «Завтрак» и «Обед». Кнопка неактивна, если приём пищи уже списан. После нажатия показать подтверждение и через несколько секунд вернуться в ожидание (или закрыть окно, когда приложат следующую карточку).
3. **Неизвестная карточка.** Сообщение и кнопка «Зарегистрировать» (если нужно, с паролем администратора).
4. **Администрирование.** Список учеников (поиск, добавление, редактирование, удаление), кнопка «Обновить Excel-файл сейчас», путь к файлу выгрузки.

Каждое окно — отдельный `.ui`-шаблон, как уже сделано для `window.ui`.

## 6. Выгрузка в Excel

**Один файл, каждый день на своём листе.**

- Файл `столовая.xlsx` в настраиваемой папке (по умолчанию `~/Документы/Столовая/`).
- **Лист на каждый день, когда была выдача.** Название листа — дата прикладывания в формате `14.10.2026` (Excel ограничивает имя листа 31 символом и запрещает `[]:*?/\`, дата с точками подходит). Дни без выдачи (выходные, каникулы) листа не получают.
- Столбцы листа дня: ФИО, группа, дата, время завтрака (или «—»), время обеда (или «—»). Внизу итоговая строка: сколько выдано завтраков и обедов.
- Листы идут по порядку дат. При открытии файла активен лист последнего дня.
- Первый лист «Итого»: по строке на каждый день (дата, завтраков, обедов) для быстрого обзора.

**Как это реализуется.** `libxlsxwriter` создаёт файлы, но не редактирует существующие. Поэтому при каждой выгрузке файл **пересобирается целиком** из журнала `meals`: все дни, лист за листом. Для столовой это тысячи строк, на это уходят доли секунды.

- Запись во временный файл `столовая.xlsx.tmp`, затем атомарная замена через `rename()`. Если сбой случится во время записи, старый файл останется целым.
- Если файл открыт в Excel на сетевом диске Windows, замена может не пройти, потому что Windows блокирует открытый файл. Тогда повторить попытку позже и показать предупреждение в интерфейсе.
- В таблице `exports` хранится дата последней удачной выгрузки. По ней при запуске видно, нужно ли пересобрать файл.

**Когда выгружать.**

- Сразу после полуночи (в файл попадает только что закончившийся день).
- При запуске программы, если последняя выгрузка была раньше вчерашнего дня (компьютер был выключен).
- По кнопке в администрировании.
- Если программа не может работать круглосуточно, альтернатива — `systemd --user` timer, который вызывает `<бинарник> --export`.

**Рост файла.** За учебный год набирается около 170 рабочих дней, то есть около 170 листов. Excel и LibreOffice с этим справляются, но листать неудобно. Если нужно, можно начинать новый файл каждый учебный год (`столовая_2026-2027.xlsx`) — см. вопросы к заказчику.

## 9. Выбор NFC-считывателя для Linux

### Как это работает в Linux

Нормальный путь для USB-считывателей — **PC/SC**: служба `pcscd` + универсальный драйвер `libccid`. Считыватели стандарта CCID работают без драйверов производителя. UID карточки читается одной стандартной командой `FF CA 00 00 00` (GET DATA), одинаковой для всех таких считывателей. Значит, `PcscReader` будет работать с любой моделью из списка ниже без изменений в коде.

Проверка считывателя: `sudo apt install pcscd pcsc-tools`, затем `pcsc_scan`. Если при прикладывании карты появляется ATR, считыватель работает.

### Сравнение

Наличие в списке проверено по `/etc/libccid_Info.plist` из пакета `libccid` 1.7.1 (Ubuntu 26.04).

| Считыватель | Подключение | В списке `libccid` | Замечания |
|-------------|-------------|:------------------:|-----------|
| **ACS ACR1252U** | PC/SC (CCID) | ✅ | **Рекомендую.** Распространён, недорог, не конфликтует с драйверами ядра |
| ACS ACR1552U | PC/SC (CCID) | ✅ | Более новая модель ACS, тоже подходит |
| Identiv uTrust 3700 F / 3720 | PC/SC (CCID) | ✅ | Хорошая альтернатива |
| HID OMNIKEY 5022 / 5422 | PC/SC (CCID) | ✅ | Надёжные, но дороже |
| Elatec TWN4 SmartCard NFC | PC/SC (CCID) | ✅ | Читает и 13,56 МГц, и 125 кГц, дорогой |
| ACS ACR122U | PC/SC (CCID) | ✅ | Самый дешёвый и частый, но **с проблемами** (см. ниже) |
| «USB RFID reader 13,56 МГц» без бренда | эмуляция клавиатуры | — | Драйверы не нужны, печатает номер и Enter (см. ниже) |

### ACR122U: почему не рекомендую

- Модуль ядра `pn533_usb` объявляет поддержку USB-id `072F:2200` (это ACR122U) и захватывает устройство раньше `pcscd`. На этой машине модуль есть (`/lib/modules/7.0.0-38-generic/kernel/drivers/nfc/pn533/`), блэклиста нет. Чтобы считыватель заработал, нужно занести модули `nfc`, `pn533`, `pn533_usb` в блэклист в `/etc/modprobe.d/`.
- По отзывам пользователей, ревизия **ACR122U-A9** часто не инициализируется даже с блэклистом.
- Модель старая, ACS сама предлагает ACR1252U на замену.

Если ACR122U уже куплен, им можно пользоваться: занести модули в блэклист и проверить через `pcsc_scan`.

### Считыватели в режиме клавиатуры

Дешёвые считыватели без бренда, которые «печатают» номер карточки (обычно 10 десятичных цифр, 4 байта UID) и нажимают Enter.

- ➕ работают где угодно без драйверов; на этапе 3 хватит `SimulatedReader` с невидимым полем ввода;
- ➖ номер попадает в окно, у которого фокус; программа не видит, подключён ли считыватель;
- ➖ формат вывода (порядок байт, десятичный или hex) отличается у разных моделей, поэтому номер одной и той же карточки у двух моделей может не совпасть;
- ➖ читают только UID (для этой задачи этого достаточно).

### Важно: 125 кГц и 13,56 МГц

Во многих школах уже есть карточки пропускной системы. Часто это **EM-Marine на 125 кГц**, а они **не NFC** и считывателями 13,56 МГц не читаются. Прежде чем покупать считыватель, нужно узнать, какие карточки будут у учеников:

- **MIFARE Classic, Ultralight, NTAG (13,56 МГц)** → любой PC/SC-считыватель из таблицы (лучше ACR1252U);
- **EM-Marine / EM4100 (125 кГц)** → нужен считыватель на 125 кГц (обычно в режиме клавиатуры) или двухчастотный, например Elatec TWN4;
- **телефоны** как карточки не подойдут: Android при эмуляции карты выдаёт случайный UID.

### Вывод для плана

1. Рекомендуемый считыватель: **ACS ACR1252U** через `pcscd` + `libccid`.
2. Реализовать `PcscReader` через `libpcsclite`: опрос `SCardGetStatusChange` в отдельном потоке, затем `FF CA 00 00 00` для чтения UID.
3. Хранить UID как `uint64`: 4-байтовый UID помещается в `uint32`, но не в `int32`, а 7-байтовый требует 64 бита.
4. Учитывать, что UID-карточку можно скопировать. Для столовой это обычно допустимо, но решение должен принять заказчик.
